# 开发文档 — 架构与升级日志

## 架构
```
src/
  data/        配置表（纯数据）
    items.ts       物品：类型、堆叠、食物数值、燃料值、装备槽、工具类型、伤害、光照、保暖、护甲、耐久
    world.ts       资源节点、建筑、生物、配方（分页）、旅程、石碑文本
  systems/     纯逻辑系统（不依赖渲染，可单独测试）
    inventory.ts   InventorySystem：15 格背包、堆叠、耐久、装备槽
    survival.ts    SurvivalSystem：生命 / 饥饿 / 精神 / 体温，以及环境影响
    time.ts        TimeSystem：一天 480 秒、四个时段、光照等级、色调、环境温度
    weather.ts     WeatherSystem：降雨的生成与强度平滑变化
    creatures.ts   CreatureSystem：生成、游荡 / 逃跑 / 追击 / 前摇攻击 / 离开，击退
    building.ts    BuildingSystem：合法位置检测
  game/
    state.ts       SaveSystem + CraftingSystem：存档 v2 结构、制作、旅程进度、设置
    game.ts        主控：场景状态机，调度各系统，处理输入与互动
    render.ts      渲染管线：地面、水、y 排序物体、建筑、生物、粒子、迷雾、雨、昼夜光照、屏幕效果、地图
  world/       map（固定种子地图生成）· ground（地面烘焙）· fog（探索迷雾）
  art/         painters / painters2（程序化美术）· manifest（资源表与 PNG 替换接口）
  engine/      math · input（键盘 / 摇杆 / 攻击）· audio（WebAudio 合成音效、音乐、雨声）
  ui/ui.ts     UIManager：HUD、属性表盘、时钟、物品栏、制作分页、篝火 / 储物箱面板、建造栏、死亡与结局画面
```

**新增内容的方法**：新物品在 `items.ts` 加一项，再在 `painters2.ts` 的 `paintIcon2` 里加图标；新配方在 `RECIPES` 加一行；新资源节点在 `NODES` 加一项，并在地图生成时散布；新生物在 `CREATURES` 加一项，补上帧绘制，生成规则写在 `game.updateCreatures`。

## 技术栈说明
项目实际没有使用 Phaser，也没有在本地运行过 Vite：开发环境无法访问 npm 仓库，所以用的是自研 Canvas 引擎 + esbuild（`scripts/build.mjs`）。`vite.config.ts` 和 `package.json` 中的 Vite 脚本已经配好，可以在有网络的机器上使用。逻辑层（data / systems / state）与渲染无关，将来可以迁移到 Phaser。

## 第 7 阶段：测试中发现并修复的问题
1. **制作面板每 0.2 秒重建一次**，按钮在点击时被替换，玩家点击可能落空 → 只有内容变化时才重新渲染。
2. **手持燃烧中的火把时，物品栏每帧重建**（耐久每帧都在变）→ 耐久按整百分比参与变化判断。
3. **「活到第 2 天」目标永远无法完成**：任务只在黎明检查，而黎明开始时仍是第 1 天 → 改为日期变化时检查。
4. **互动目标不考虑朝向**：树或篝火旁边有草丛时，总是选中草丛 → 优先选择面朝方向的目标；缺工具的目标排在后面。
5. **光照层开销大**（单帧渲染 62 ms，在无头软件渲染下测得）→ 光照层改为半分辨率，单帧更新加渲染降到约 2.7 ms。
6. 黎明的提示显示了错误的天数 → 黎明和新的一天分别提示。
7. 窄屏上的长提示文字溢出屏幕 → 改为自动换行。

## 已知限制
- 地上的掉落物不保存（读档后消失）；生物不保存（读档后重新生成）。
- 目前没有拆除建筑的功能。
- 第二批扩展系统（烹饪锅、农业、季节、BOSS 等）尚未实现。
- 所有美术都是程序化绘制，正式的手绘资源待补，见 `ART_GUIDE.md`。
