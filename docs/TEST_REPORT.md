# 测试报告 — v2 生存版

- **日期**：2026-11-21
- **环境**：Headless Chromium（Playwright），Linux。桌面 1366×768；移动端使用 iPhone 13 预设（390×844，触屏）并切换到横屏 844×390
- **被测文件**：`dist/index.html`（esbuild 生产构建）
- **结果**：**60 / 60 通过**，耗时 325 秒，浏览器控制台 **0 条错误或警告**
- **复现方法**：`npm run test:e2e`，截图生成在 `tests/output/v2_*.png`；原始数据见 `docs/test-results.json`

## 方法
移动、采集、制作、建造、战斗全部通过**真实的键盘、鼠标、触屏事件**完成。页面内的自动导航只负责决定按哪个方向键，角色没有瞬移。

标有 **[钩子]** 的项目使用了测试钩子 `window.__LITM__`，原因如实列在这里：
- **加快时间**（`debug.timeScale = 60`）：一天在真实时间里是 8 分钟，不加速就无法在几分钟内测完昼夜。加速期间，测试会持续给篝火补满燃料、保持角色不挨饿，相当于玩家一直在添柴和吃东西。
- **直接设置饥饿、生命**：用来验证进食效果和死亡流程。
- **生成雾狼并把时间调到黄昏**：雾狼只在第 2 天以后的夜里随机出现，而且天亮会离开。
- **强制降雨**：降雨的出现时间是随机的。

## 测试中发现并修复的问题
1. 制作面板每 0.2 秒重建一次，导致点击落空。这是真实缺陷，玩家也会遇到。
2. 手持燃烧中的火把时，物品栏每帧重建，导致点击落空。这也是真实缺陷。
3. 「活到第 2 天」的目标永远无法完成。
4. 互动目标不考虑角色朝向，树或篝火旁有草丛时总是选中草丛。
5. 光照层的渲染开销过大（62 ms → 2.7 ms）。
6. 窄屏上的长提示溢出屏幕。

测试脚本自身的问题（不是游戏缺陷）：雾狼被生成在树后面导致无法接近；雾狼白天会离开，所以需要先把时间调到黄昏；无头环境的帧间隔约 83 ms，超过了单帧时间上限 0.05 秒，导致游戏时间只按真实时间约 0.6 倍推进，因此所有涉及时间的断言都改成了等待条件成立。

## 性能
- 单帧更新加渲染的 CPU 耗时：中位数约 2.7 ms，P95 约 5 ms（1366×768）。
- 无头 Chromium 的 rAF 间隔约 83 ms。这是测试环境合成器的限制：v1 和 v2 在这里的数值相同，不代表游戏本身的帧率。真实浏览器上的帧率**没有测过**。
